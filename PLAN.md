# План: Telegram-бот напоминаний

Это рабочий чек-лист. Claude Code отмечает `[x]` по мере выполнения, чтобы в любой новой сессии было видно, где мы остановились.
Правила и архитектура описаны в `CLAUDE.md`, здесь только «что делаем и в каком порядке».

> 💡 так помечены пояснения для джуна.

---

## Фаза 0. Подготовка (один вечер, руками)

- [x] Создать бота у @BotFather и получить токен
  > 💡 Токен — пароль бота. Не кладём его ни в код, ни в GitHub.
- [x] Узнать свой Telegram user_id (например, через @userinfobot)
  > 💡 Нужен для whitelist: бот будет отвечать только тебе.
- [x] Создать новый проект в Supabase (регион EU)
- [x] Установить Supabase CLI, выполнить `supabase login` и `supabase link`
  > 💡 CLI — консольная утилита: через неё из VS Code заливаешь функции и миграции в облако.
- [x] Получить API-ключ Groq (console.groq.com)
- [x] Создать репозиторий на GitHub, положить `CLAUDE.md` и `PLAN.md`, добавить `.gitignore` с `.env`
- [x] Положить секреты в Supabase Secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ALLOWED_USER_ID`, `GROQ_API_KEY`, `GROQ_LLM_MODEL`, `TICK_SECRET`
  > 💡 Секреты хранятся на стороне Supabase, код читает их как переменные окружения.

✅ **Готово, когда:** `supabase link` прошёл, секреты видны в панели Supabase.

## Фаза 1. MVP: «написал → напомнил» (2–3 вечера)

- [x] Миграция: таблицы `reminders`, `settings`, `sessions` и индекс
  > 💡 Миграция — SQL-файл, который создаёт или меняет таблицы. Лежит в git, поэтому история изменений базы видна.
  > 💡 Поле `rrule` для повторов создаём сразу, хотя логику повторов делаем в фазе 2, чтобы потом не переделывать таблицу.
- [x] Таблица тестов для парсера: 30–50 русских фраз → ожидаемая дата
  > 💡 Сначала описываем, «как должно быть», потом пишем код. Тесты ловят ошибки после каждого изменения.
- [x] Парсер дат на правилах: «завтра в 11», «через 2 часа», «3 октября в 15:00», дни недели
- [x] Fallback на Groq LLM для фраз, которые правила не поняли
- [x] Edge Function `bot`: whitelist + проверка секретного заголовка Telegram
  > 💡 Webhook: Telegram сам присылает каждое твоё сообщение на адрес функции. Функция просыпается, обрабатывает его и засыпает.
- [x] Карточка подтверждения: «Напомню 29.10 в 11:00: встреча» [✅ OK] [🕐 Другое время]
  > 💡 Защищает от ошибок парсера: ничего не сохраняется без твоего OK.
- [x] Edge Function `tick`: забрать наступившие напоминания, отправить, отметить
  > 💡 Забираем записи «атомарно», одним запросом с пометкой `sending`, чтобы при двойном запуске не было двойной отправки.
- [x] Настроить pg_cron, который каждую минуту вызывает `tick`
  > 💡 Функции ничего не помнят и не «ждут» времени сами, поэтому раз в минуту их будит база.
- [x] Команда `/list` и удаление напоминания
- [x] Зарегистрировать webhook у Telegram

✅ **Готово, когда:** напоминание «через 3 минуты» приходит на телефон.

## Фаза 2. Управление и повторы (2–3 вечера)

- [x] Кнопки под сработавшим напоминанием: [+10 мин] [+1 час] [Завтра] [✅ Готово] (проверено на телефоне)
  > 💡 Это inline-кнопки: нажатие приходит боту как событие `callback_query`, бот меняет запись в базе.
- [x] Редактирование: ✏️ текст и 🕐 время из `/list`, «✏️ Текст» на карточке до OK и «✏️ Изменить» после (старый текст показывается копируемым; проверено на телефоне)
  > 💡 Бот спрашивает «Введи новый текст» и должен понять, что следующее сообщение — ответ на этот вопрос. Такое состояние храним в таблице `sessions`.
- [ ] Inline-календарь из кнопок: месяц → день → час → минуты
- [x] Повторы: разбор фраз «каждый день / понедельник / будний день в 9» в `rrule` (проверено на телефоне)
  > 💡 RRULE — стандартная строка-описание повтора (её же используют Google Calendar и Outlook).
- [x] После отправки повторяющегося напоминания `tick` считает следующую дату, а не закрывает его
- [x] «⛔ Прекратить повторы» под напоминанием по расписанию; правка расписания через «✏️ Время» («каждый…» заменяет расписание)

- [x] «Настойчивое» напоминание: кнопка «🔁 Повторять» на карточке, повтор каждые N минут (всего M раз), кнопка «✅ Готово» под сообщением останавливает (сделано раньше остальных пунктов фазы 2, проверено на телефоне)
  > 💡 Это серия сообщений об одном срабатывании (колонки `nag_*`), а не расписание RRULE.

✅ **Готово, когда:** «каждый будний день в 9 зарядка» срабатывает два дня подряд, snooze переносит напоминание.

## Фаза 4. Голос (1–2 вечера)

- [ ] Голосовое → скачать через `getFile` → Groq Whisper (`language=ru`) → текст
- [ ] Текст идёт в тот же парсер и в карточку «Я услышал: …, напомню …» [OK] [Изменить]
  > 💡 Голос — просто ещё один способ получить текст, дальше логика общая.
- [ ] Опция: сохранить само голосовое как вложение

✅ **Готово, когда:** наговорил «послезавтра в 8 позвонить маме», и напоминание создано верно.
