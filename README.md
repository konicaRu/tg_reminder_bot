## 📆 Повторы по расписанию

Фразы: «каждый день в 9», «ежедневно», «каждое утро», «по будням», «по выходным», «каждый понедельник», «каждый вторник и четверг в 19». Время можно не указывать, тогда 09:00.

- На карточке: `📆 Повторяется по будням в 09:00`. Расписание хранится строкой RRULE (`FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=9;BYMINUTE=0`), время внутри, поэтому snooze не сдвигает расписание.
- **[✅ Готово]** закрывает только это срабатывание, расписание продолжается. **[⛔ Прекратить повторы]** заканчивает его совсем, 🗑 в `/list` тоже.
- Если бот простоял, придёт одно сообщение, а не пачка пропущенных.
- Можно сочетать с «🔁 Повторять» (каждые N минут на каждое срабатывание).
- Пока не умеем: «каждые 2 недели», «каждый месяц», «каждый год» (бот честно скажет).

## 🔁 Настойчивое напоминание

На карточке подтверждения кнопка **«🔁 Повторять»** включает серию: по умолчанию каждые 5 минут, всего 10 сообщений
(«⏰ Напоминание (2 из 10)»). Интервал (5/10/30/60 мин) и количество (3/5/10/20) выбираются кнопками. Под каждым
сообщением серии кнопка **«✅ Готово»**: нажатие останавливает повторы. У предыдущего сообщения кнопка убирается сама.

Как это устроено и *почему так*:
- Серия живёт в трёх колонках таблицы `reminders` (`nag_interval_min`, `nag_total`, `nag_sent`), а не в `rrule`: это
  повторы одного срабатывания, а не расписание («каждый будний день» — отдельная задача фазы 2).
- После каждой отправки `tick` возвращает запись в очередь на «начало текущей минуты + интервал». Округление вниз нужно,
  потому что `tick` просыпается ровно в :00, а отправка идёт на секунду позже: без него 5 минут превращались бы в 6.
- Обновление записи условное (`where status = 'sending'`): если «Готово» или 🗑 нажали, пока шла отправка, решение
  пользователя главнее, и серия не возобновляется.
- Данные кнопок приходят извне, поэтому бот принимает только значения из списка кнопок; на уровне базы стоит потолок
  (до 50 сообщений, интервал до суток), чтобы ошибка настройки не превратилась в спам.

## 🧩 Как это устроено

```
                    ┌──────────────────────────┐
 Telegram ─webhook─►│ Edge Function `bot`      │──► Postgres
                    │ разбор, кнопки, запись   │    (reminders, settings, sessions)
                    └──────────────────────────┘          ▲
                                                          │ забирает наступившие
 pg_cron (раз в минуту) ─pg_net─► Edge Function `tick` ───┘
                                  отправка напоминаний
```

Нетривиальные решения и **почему** они такие:

- **Функции не хранят состояние в памяти.** Edge Function «просыпается» на запрос и засыпает, поэтому всё, включая состояние диалога («жду новый текст напоминания»), лежит в таблице `sessions`.
- **`tick` идемпотентный.** Он забирает записи одним атомарным запросом
  `UPDATE … SET status='sending' WHERE status='pending' AND remind_at <= now() RETURNING …`.
  Если его вызвали дважды, вторая копия ничего не найдёт и дубля сообщения не будет.
- **Просрочка досылается.** Если `tick` пропустил минуту из-за сбоя, следующий запуск отправит всё просроченное.
- **Время хранится в UTC** (`timestamptz`), пользователю показывается в его поясе (по умолчанию `Europe/Moscow`). Так нет путаницы с переходами и серверным часовым поясом.
- **Планировщик живёт в базе.** Функция сама не умеет «ждать» нужного времени, поэтому раз в минуту её будит `pg_cron`.

### Разбор дат: два уровня
1. **Правила** (быстро и бесплатно): «сегодня/завтра», «через N минут/часов/дней», «в 11:30», «3.10», дни недели, «каждый день/понедельник/будний день».
2. **Groq LLM** — запасной вариант, если правила не поняли фразу. Модель возвращает строгий JSON, ответ валидируется; при ошибке бот вежливо просит уточнить.

Соглашения: время не указано → 09:00; «в 5» → ближайшие 05:00 или 17:00; время уже прошло → предложить завтра.

## 🛠 Стек и почему он такой

| Что | Чем | Зачем |
|---|---|---|
| Код бота | Supabase Edge Functions (Deno, TypeScript) | Serverless и бесплатно |
| Telegram-фреймворк | [grammY](https://grammy.dev) | Стандарт для Deno, есть пример у Supabase |
| База | Supabase Postgres | Отдельный проект на free-тарифе |
| Планировщик | `pg_cron` + `pg_net` | Раз в минуту вызывает `tick` |
| Голос → текст | Groq, `whisper-large-v3`, `language=ru` | Бесплатно, без карты |
| Сложные даты | Groq LLM (модель в `GROQ_LLM_MODEL`) | Fallback к правилам |
| Повторы | RRULE (RFC 5545) + `npm:rrule` | Тот же формат, что в Google Calendar |
| Mini App | GitHub Pages + Telegram WebApp SDK | Нативный выбор даты |
| Тесты | `deno test` | Особенно для парсера дат |

Внешние сервисы, кроме Telegram, Supabase и Groq, не добавляем без согласования.

## 📁 Структура репозитория

```
supabase/
  functions/
    bot/                # webhook: handlers.ts (логика диалога), index.ts (grammY, whitelist, секрет)
    tick/               # logic.ts + index.ts: отправка наступивших напоминаний
    set-webhook/        # одноразовая функция: регистрирует webhook у Telegram с сервера
    _shared/
      parser/           # mod.ts (разбор дат на правилах), tz.ts (пояса), tests/
      groq.ts           # запасной разбор фраз через Groq LLM
      telegram.ts       # карточка, список, кнопки, формат дат
      telegram_api.ts   # вызовы Bot API (с очисткой токена из ошибок)
      db.ts             # все запросы к базе
      tests/            # тесты общего кода (+ интеграционные тесты БД)
  migrations/           # SQL-миграции: таблицы и расписание pg_cron
miniapp/                # фаза 5 (пока нет)
CLAUDE.md               # правила работы для Claude Code
PLAN.md                 # чек-лист по фазам
```

Тесты: `cd supabase/functions && deno test` (интеграционные тесты базы пропускаются без `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`).

## 🚀 Развернуть с нуля

Подробный чек-лист с пояснениями — в [PLAN.md](PLAN.md), фаза 0. Ниже — порядок, проверенный на практике.

1. **BotFather** → создать бота, получить токен. *Токен — пароль бота, в код и git его не кладём.*
2. Узнать свой Telegram `user_id` (например, через @userinfobot) — для whitelist.
3. Создать проект **Supabase** (регион EU).
4. Установить **Supabase CLI**, затем `supabase login` и `supabase link --project-ref <ref>`.
5. Получить ключ **Groq** на console.groq.com. Какие модели доступны именно твоему ключу, зависит от аккаунта: в проверенной установке работала `openai/gpt-oss-120b` (а `llama-3.3-70b-versatile` отвечала `model_not_found`).
6. Скопировать `.env.example` в `.env`, заполнить, затем загрузить секреты в Supabase:
   ```bash
   supabase secrets set --env-file .env
   ```
   `TELEGRAM_WEBHOOK_SECRET` и `TICK_SECRET` — это длинные случайные строки (например, 64 hex-символа), придумай их сам.
7. Задеплоить функции (обе с `--no-verify-jwt`: Telegram и pg_cron не умеют слать JWT Supabase, защита — собственные секреты):
   ```bash
   supabase functions deploy bot  --no-verify-jwt --use-api   # --use-api: без Docker
   supabase functions deploy tick --no-verify-jwt --use-api
   ```
8. Применить миграции: `supabase db push`. Если он падает с `Connection error`, примени файлы по порядку командой
   `supabase db query --linked -f supabase/migrations/<файл>.sql` и запиши их в таблицу истории `supabase_migrations.schema_migrations`.
9. Положить `TICK_SECRET` в **Vault** (расписание читает его оттуда, в git его нет), например через SQL Editor:
   ```sql
   select vault.create_secret('<значение TICK_SECRET>', 'tick_secret');
   ```
10. Зарегистрировать webhook с сервера (с некоторых сетей `api.telegram.org` недоступен): задеплоить `set-webhook`,
    вызвать `POST` с заголовком `x-tick-secret`, проверить `GET` (адрес верный, нет `last_error_message`), затем удалить функцию:
    ```bash
    supabase functions deploy set-webhook --no-verify-jwt --use-api
    curl -X POST https://<ref>.supabase.co/functions/v1/set-webhook -H "x-tick-secret: <TICK_SECRET>"
    supabase functions delete set-webhook
    ```
11. Проверка: `bot` и `tick` без секрета отвечают `401`; в Telegram бот отвечает на `/start`; `select * from cron.job` показывает задание `tick-every-minute`.

## 🔒 Безопасность

| Что | Как |
|---|---|
| Секреты | Только в Supabase Secrets, не в коде и не в git. `.env` в `.gitignore` |
| Webhook `bot` | Деплой с `--no-verify-jwt`, поэтому обязательна проверка заголовка `X-Telegram-Bot-Api-Secret-Token` |
| Функция `tick` | Деплой с `--no-verify-jwt` (pg_cron не шлёт JWT), поэтому проверяет свой секрет `TICK_SECRET` в заголовке `x-tick-secret` (сравнение за постоянное время); без него `401` |
| Токен бота | Входит в адрес запросов к Telegram, поэтому ошибки сети «чистятся» от адреса перед записью в логи; текст напоминаний в логи не пишется |
| Whitelist | На сообщения не от людей из `ALLOWED_USER_ID` бот не отвечает. В секрете один id или несколько через запятую: `234320036,111222333` |

Секреты: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ALLOWED_USER_ID`, `GROQ_API_KEY`, `GROQ_LLM_MODEL`, `TICK_SECRET`.

### 🎙 Голосовые и приватность
Голосовое скачивается из Telegram и уходит в Groq (Whisper) на распознавание; у нас аудио не хранится, ни аудио, ни распознанный текст не пишутся в логи. Лимиты: до 60 секунд и 5 МБ. Модель по умолчанию `whisper-large-v3`, сменить можно необязательным секретом `GROQ_STT_MODEL`. Без `GROQ_API_KEY` голос выключен.

### 👨‍👩‍👧 Как дать доступ семье
1. Человек пишет @userinfobot и присылает вам свой числовой id.
2. Вы добавляете id в секрет через запятую: `supabase secrets set ALLOWED_USER_ID=234320036,111222333`.
3. Передеплойте бота: `supabase functions deploy bot --no-verify-jwt --use-api` (секрет читается при запуске функции).
4. Человек открывает бота и нажимает `/start` (Telegram не даёт боту писать первым).

Напоминания у каждого свои (разделены по `chat_id`), часовой пояс у всех Москва. Вы как администратор технически видите все записи в базе Supabase. Лимиты бесплатных тарифов Groq и Supabase общие.

## 💡 Бэклог

- Утренняя сводка «на сегодня у тебя: …»
- Статистика выполненных напоминаний
- Резервная LLM (Gemini, бесплатный тариф) на случай, если Groq недоступен или лимитирован
- Слово «напомни» вырезается из текста только в начале фразы; «через минуту напомни …» оставляет «напомни» в тексте
- Напоминание, которое стабильно не отправляется (например, бот заблокирован), `tick` пробует каждую минуту бесконечно: нужен счётчик попыток
- Если сообщение ушло, а статус `sent` записать не удалось (двойной сбой), через 5 минут возможен повторный показ
- Интеграционные тесты базы нестабильно работают из сети в РФ (Deno-клиент «залипает»): запускать их на CI или другом хосте
- Слова про время суток без цифр («после обеда», «утром») правила игнорируют: время берётся по умолчанию, карточка позволяет поправить
