## ✨ Что умеет

| Возможность | Пример | Фаза |
|---|---|---|
| Текст → напоминание | «через 3 минуты», «3 октября в 15:00» | 1 |
| Карточка подтверждения | «Напомню 29.10 в 11:00: встреча» **[✅ OK] [🕐 Другое время]** | 1 |
| Список и удаление | `/list` | 1 |
| Snooze и «Готово» | **[+10 мин] [+1 час] [Завтра] [✅ Готово]** | 2 |
| Повторы | «каждый будний день в 9 зарядка» | 2 |
| Фото и документы | картинка с подписью приходит вместе с напоминанием | 3 |
| Голосовые | наговорил — бот распознал и создал напоминание | 4 |
| Mini App | системный выбор даты на телефоне | 5 |

> Ничего не сохраняется без карточки подтверждения: так ошибка разбора даты не превратится в пропущенную встречу.

## 🧩 Как это устроено

```
                    ┌──────────────────────────┐
 Telegram ─webhook─►│ Edge Function `bot`      │──► Postgres
                    │ разбор, кнопки, запись   │    (reminders, settings, sessions)
                    └──────────────────────────┘          ▲
                                                          │ забирает наступившие
 pg_cron (раз в минуту) ─pg_net─► Edge Function `tick` ───┘
                                  отправка напоминаний
```

Нетривиальные решения и **почему** они такие:

- **Функции не хранят состояние в памяти.** Edge Function «просыпается» на запрос и засыпает, поэтому всё, включая состояние диалога («жду новый текст напоминания»), лежит в таблице `sessions`.
- **`tick` идемпотентный.** Он забирает записи одним атомарным запросом
  `UPDATE … SET status='sending' WHERE status='pending' AND remind_at <= now() RETURNING …`.
  Если его вызвали дважды, вторая копия ничего не найдёт и дубля сообщения не будет.
- **Просрочка досылается.** Если `tick` пропустил минуту из-за сбоя, следующий запуск отправит всё просроченное.
- **Время хранится в UTC** (`timestamptz`), пользователю показывается в его поясе (по умолчанию `Europe/Moscow`). Так нет путаницы с переходами и серверным часовым поясом.
- **Планировщик живёт в базе.** Функция сама не умеет «ждать» нужного времени, поэтому раз в минуту её будит `pg_cron`.

### Разбор дат: два уровня
1. **Правила** (быстро и бесплатно): «сегодня/завтра», «через N минут/часов/дней», «в 11:30», «3.10», дни недели, «каждый день/понедельник/будний день».
2. **Groq LLM** — запасной вариант, если правила не поняли фразу. Модель возвращает строгий JSON, ответ валидируется; при ошибке бот вежливо просит уточнить.

Соглашения: время не указано → 09:00; «в 5» → ближайшие 05:00 или 17:00; время уже прошло → предложить завтра.

## 🛠 Стек и почему он такой

| Что | Чем | Зачем |
|---|---|---|
| Код бота | Supabase Edge Functions (Deno, TypeScript) | Serverless и бесплатно |
| Telegram-фреймворк | [grammY](https://grammy.dev) | Стандарт для Deno, есть пример у Supabase |
| База | Supabase Postgres | Отдельный проект на free-тарифе |
| Планировщик | `pg_cron` + `pg_net` | Раз в минуту вызывает `tick` |
| Голос → текст | Groq, `whisper-large-v3`, `language=ru` | Бесплатно, без карты |
| Сложные даты | Groq LLM (модель в `GROQ_LLM_MODEL`) | Fallback к правилам |
| Повторы | RRULE (RFC 5545) + `npm:rrule` | Тот же формат, что в Google Calendar |
| Mini App | GitHub Pages + Telegram WebApp SDK | Нативный выбор даты |
| Тесты | `deno test` | Особенно для парсера дат |

Внешние сервисы, кроме Telegram, Supabase и Groq, не добавляем без согласования.

## 🚀 Развернуть с нуля

Подробный чек-лист с пояснениями — в [PLAN.md](PLAN.md), фаза 0. Коротко:

1. **BotFather** → создать бота, получить токен. *Токен — пароль бота, в код и git его не кладём.*
2. Узнать свой Telegram `user_id` (например, через @userinfobot) — для whitelist.
3. Создать проект **Supabase** (регион EU).
4. Установить **Supabase CLI**, затем `supabase login` и `supabase link`.
5. Получить ключ **Groq** на console.groq.com.
6. Положить секреты в Supabase Secrets (список ниже).
7. Применить миграции и задеплоить функции:
   ```bash
   supabase db push
   supabase functions deploy bot --no-verify-jwt   # Telegram не умеет слать JWT Supabase
   supabase functions deploy tick
   ```
8. Зарегистрировать webhook у Telegram (с `secret_token`).

> Пункты 7–8 станут актуальны в фазе 1; точные команды будут уточнены, когда появится код.

## 🔒 Безопасность

| Что | Как |
|---|---|
| Секреты | Только в Supabase Secrets, не в коде и не в git. `.env` в `.gitignore` |
| Webhook `bot` | Деплой с `--no-verify-jwt`, поэтому обязательна проверка заголовка `X-Telegram-Bot-Api-Secret-Token` |
| Функция `tick` | Проверяет свой секрет `TICK_SECRET` |
| Whitelist | На сообщения не от `ALLOWED_USER_ID` бот не отвечает |

Секреты: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ALLOWED_USER_ID`, `GROQ_API_KEY`, `GROQ_LLM_MODEL`, `TICK_SECRET`.
