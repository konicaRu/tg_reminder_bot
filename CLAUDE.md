# Telegram-бот напоминаний — инструкция для Claude Code

## О проекте
Личный Telegram-бот напоминаний для одного пользователя (владельца).
Пишешь или наговариваешь «завтра в 11 встреча», и в нужное время бот присылает сообщение.
Главный сценарий — работа с телефона. Всё должно работать на бесплатных тарифах.

**Владелец — продуктовый аналитик (SQL, Python), в TypeScript/Deno и бэкенде уровень джуна.**
Поэтому:
- в коде пиши понятные комментарии на русском: что делает блок и зачем;
- перед каждой фазой показывай план простыми словами и жди согласия;
- новые термины (webhook, миграция, callback и т.п.) объясняй в одном-двух предложениях.

## Стек
| Что | Чем | Зачем |
|---|---|---|
| Код бота | Supabase Edge Functions (Deno, TypeScript) | Серверless: функция просыпается на запрос, не засыпает «насовсем», бесплатно |
| Telegram-фреймворк | grammY (`npm:grammy` / `https://deno.land/x/grammy`) | Стандарт для Deno, есть пример у Supabase |
| База | Supabase Postgres | Отдельный проект на free-тарифе |
| Планировщик | `pg_cron` + `pg_net` | Раз в минуту вызывает функцию `tick` |
| Голос → текст | Groq API, модель `whisper-large-v3`, `language=ru` | Бесплатный тариф без карты |
| Сложные даты | Groq API, LLM-модель из env `GROQ_LLM_MODEL` | Fallback, когда правила не поняли фразу |
| Повторы | Строка RRULE (RFC 5545) + `npm:rrule` | Стандартный формат «каждый понедельник в 9» |
| Mini App (фаза 5) | Статическая страница на GitHub Pages + Telegram WebApp SDK | Нативный выбор даты на телефоне |
| Тесты | `deno test` | Особенно для парсера дат |

Внешние сервисы, кроме Telegram, Supabase и Groq, не добавлять без согласования.

## Архитектура
```
Telegram ──webhook──► Edge Function `bot`   → разбор сообщения, кнопки, запись в БД
pg_cron (каждую минуту) ──► Edge Function `tick` → отправка наступивших напоминаний
```
- Функции **не хранят состояние в памяти**: всё лежит в БД, включая состояние диалогов.
- `tick` должен быть **идемпотентным**: атомарно забирает записи
  (`UPDATE ... SET status='sending' WHERE status='pending' AND remind_at <= now() RETURNING ...`),
  чтобы при двойном вызове не было двойной отправки.
- Если `tick` пропустил время (сбой), он досылает всё просроченное при следующем запуске.
- Всё время хранится в **UTC** (`timestamptz`), пользователю показывается в его поясе (по умолчанию `Europe/Moscow`).

## Модель данных (стартовая, менять через миграции)
**reminders**
- `id` uuid pk
- `chat_id` bigint
- `text` text
- `remind_at` timestamptz — ближайшее срабатывание (UTC)
- `rrule` text null — правило повтора; null = разовое
- `status` text — `pending` / `sending` / `sent` / `done` / `cancelled`
- `attachment_file_id` text null, `attachment_type` text null (`photo` / `document` / `voice`)
- `last_message_id` bigint null — id сообщения с напоминанием (для кнопок snooze)
- `created_at`, `updated_at` timestamptz

**settings**: `chat_id` pk, `timezone` text default `'Europe/Moscow'`, `default_time` time default `'09:00'`

**sessions** (состояние диалога): `chat_id` pk, `state` text, `payload` jsonb, `updated_at`

Индекс: `reminders (status, remind_at)`.

## Безопасность
- Секреты — только в Supabase Secrets, никогда в коде и в git. Файл `.env` — в `.gitignore`.
- Список секретов: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ALLOWED_USER_ID`, `GROQ_API_KEY`, `GROQ_LLM_MODEL`, `TICK_SECRET`.
- Функция `bot` деплоится с `--no-verify-jwt` (Telegram не умеет слать JWT Supabase), поэтому обязательно проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.
- Функция `tick` проверяет свой секрет `TICK_SECRET`.
- Whitelist: на сообщения не от людей из `ALLOWED_USER_ID` (один id или несколько через запятую) бот не отвечает.

## Правила разбора дат
1. Сначала **правила** (быстро, бесплатно): «сегодня/завтра/послезавтра», «через N минут/часов/дней», «в 11», «в 11:30», «3 октября», «3.10», дни недели, «каждый день/понедельник/будний день».
   Можно оценить `npm:chrono-node` на русских тестах; если слабо — свои правила.
2. Если правила не справились — **Groq LLM** с инструкцией вернуть строгий JSON:
   `{ "text": "...", "remind_at": "ISO с поясом", "rrule": "... или null", "confidence": 0..1 }`.
   Ответ валидировать; при ошибке — вежливо попросить уточнить.
3. Соглашения:
   - время не указано → `default_time` (09:00);
   - «в 5» → ближайшее будущее 05:00 или 17:00;
   - время уже прошло → предложить завтра;
   - **ничего не сохраняется без карточки подтверждения**: «Напомню 29.10 в 11:00: встреча» [✅ OK] [🕐 Другое время] [📅 Календарь].

```
  functions/
    bot/index.ts          # webhook: роутинг сообщений и кнопок
    tick/index.ts         # отправка наступивших напоминаний

      parser/             # разбор дат (+ tests/)
      groq.ts             # STT и LLM-fallback
      telegram.ts         # клавиатуры, форматирование
      db.ts               # запросы к БД
      repeat.ts           # расчёт следующей даты по rrule
  migrations/             # SQL-миграции
miniapp/                  # фаза 5, статика для GitHub Pages
CLAUDE.md
README.md                 # как развернуть с нуля
```

## Фазы (делать строго по одной)
**Фаза 0 — подготовка (руками владельца, Claude подсказывает):** BotFather → токен; новый проект Supabase (регион EU); Supabase CLI + `supabase link`; ключ Groq; репозиторий GitHub; секреты.

**Фаза 1 — MVP.** Миграции (вся модель выше, включая `rrule`), функция `bot` (whitelist, текст → парсер → карточка → сохранение), функция `tick` + pg_cron, `/list`, удаление, установка webhook.
✅ Напоминание «через 3 минуты» приходит на телефон.

**Фаза 2 — управление и повторы.** Snooze под напоминанием [+10 мин] [+1 час] [Завтра] [✅ Готово]; редактирование текста и времени из `/list`; inline-календарь из кнопок; повторы: после отправки `tick` считает следующую дату по `rrule`, кнопка «🔁 Повтор» и «прекратить повторы».
✅ «Каждый будний день в 9 зарядка» срабатывает два дня подряд, snooze переносит.

**Фаза 3 — вложения.** Фото/документ с подписью → напоминание с `file_id`; при срабатывании переотправка по `file_id`; «📎 Прикрепить» в редактировании.

**Фаза 4 — голос.** Голосовое → `getFile` → Groq Whisper → текст → тот же парсер → карточка «Я услышал: …». Голосовое можно сохранить вложением.

**Фаза 5 — Mini App.** Страница на GitHub Pages с нативным `datetime-local`, открывается кнопкой; результат отправляется в Edge Function с проверкой `initData`.

## Как работать
- Пошаговый чек-лист — в `PLAN.md`. В начале сессии смотреть, где остановились; после каждого выполненного пункта отмечать `[x]`.
- Каждую фазу начинать в plan mode: план простыми словами → согласие → код.
- Для парсера: **сначала тесты** (таблица 30–50 русских фраз → ожидаемый результат), потом код. Тесты гонять после каждого изменения.
- После каждого работающего шага — коммит с понятным сообщением на русском.
- Перед удалением данных или изменением существующих таблиц — спросить.
- Не выходить за рамки текущей фазы; идеи на потом — в раздел «Бэклог» в README.
- Тексты бота — на русском, коротко, с эмодзи на кнопках.
- Проверка фазы — на реальном телефоне, а не только «код задеплоился».
